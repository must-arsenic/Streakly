# Streakly: architecture

| Choice | Decision | Why |
|---|---|---|
| Phone app | The spec asks for Expo, but the engine builds only `next-app`. So Streakly is built as an installable web app (`public/manifest.webmanifest`, standalone display, the images step's icons) that runs in the phone's browser or from the home screen. There is no store build. **Sign only if a web app on the phone is acceptable.** | The spec header `app: expo` is something the engine can't build today. This row is where you decide whether that's OK. |
| Parts | One part, `app`: the `next-app` template, Next.js 16, in one container on port 3000. It only serves the app's files. All work runs in the browser. Folders: `src/app` (shell and screens), `src/lib` (days, streaks, store, retry, test hooks), `public` (manifest, `sw.js`, icons). `db.ts`, `auth.ts`, `uploads.ts` and `live.ts` are not used. | "Everything is stored on the phone only… nothing is sent over the network" (Data and risk). |
| Pages | One route, `/`. It is a client-rendered shell with the bottom tab bar (Today, Week, Settings) and switches screens by URL hash without fetching: `#/today` (default), `#/week`, `#/settings`, `#/habits/new` (from "+" on Today), `#/habits/<id>` (from tapping a habit's name), and `#/guide` (first-run cards, shown when `guideDone` is false). | `ac~streakly.no-network.offline~1` needs 0 network requests while adding, ticking and changing the theme. Route changes in Next would fetch RSC payloads. |
| Offline shell | `public/sw.js` is about 30 lines with no library. On install it caches the built shell. It answers same-origin GETs cache-first and is registered from `src/app/sw-register.tsx`. | The app must work when "the phone is offline" (`no-network.offline`). |
| API | None. No API routes. `contract/openapi.yaml` is written first with `paths: {}` and a note that the app has no server API. | `req~streakly.no-network~1`: habit, tick and settings data never leave the phone. |
| Data | IndexedDB in the browser, database `streakly`, through `src/lib/store.ts`. Stores: `habits` {id, name, colour 0–7, order, createdOn `YYYY-MM-DD`}, `ticks` keyed [habitId, date `YYYY-MM-DD`] with a habitId index, and `settings` {theme `system`/`light`/`dark`, guideDone}. Schema versions go in `onupgradeneeded` as an appended list, one step per change. | `req~streakly.local-storage~1`: save habits, ticks, order and theme on the phone and show them after reopening. |
| Saves | Each change is one `readwrite` transaction over every store it touches: delete habit (habit plus its ticks), delete-all (all stores, theme reset, guideDone false) and reorder (all `order` values). On-screen state changes only after `oncomplete`. On error the transaction aborts, the last saved state is shown again, and `src/lib/retry.ts` keeps the failed change so "Try again" can run it again. | `req~streakly.no-partial-saves~1` and `req~streakly.save-errors~1`: keep the old state, show "Couldn't save your change", and retry the same change. |
| Dates | `src/lib/days.ts` builds local calendar dates from `getFullYear/getMonth/getDate`, never `toISOString`. A tick is stored as the date string only. Date arithmetic goes through `new Date(y, m, d)`. Week headers use `Intl.DateTimeFormat(undefined, {weekday: 'short'})` plus the day number. `canTick(date, today)` allows only today and the 6 days before, and `store.ts` refuses anything else. | `tick-dates.time-zone`: a tick stored for 2026-11-09 stays on 2026-11-09 after a time zone change. `no-out-of-range-ticks.refused`. |
| Streaks | `src/lib/streaks.ts` holds pure functions `current(dates, today)` and `best(dates)` over a sorted set of date strings. They are worked out again from the ticks on every render, not stored. | `streak-current.*` and `streak-best.longest`: the run counts from today if ticked, else from yesterday, and the best is recalculated when ticks change. |
| Day refresh | A `useToday()` hook in `src/lib/days.ts` holds today's date. A `setTimeout` to the next local midnight and a `visibilitychange` listener (when the page becomes visible) work out today again, which re-renders tick boxes, week columns and streaks. | `req~streakly.day-refresh~1`: refresh at midnight and when the app returns to the foreground, without a restart. |
| Reorder | Long-press (500 ms) on a Today row, then drag with pointer events. This is hand-written with no library. On drop, the new order is saved in one transaction. | `req~streakly.habit-reorder~1`: long-press and drag, and the order sticks on every screen and after a restart. |
| Form | Add and Edit share `src/app/habit-form.tsx`. The name field uses `maxLength={40}` and is trimmed before checking. "Give your habit a name" shows when the trimmed name is empty. "Save" is disabled while saving. On failure it shows "Couldn't save. Try again." and keeps what was typed. There are 8 colour swatches, with the first preselected. | `req~streakly.form-states~1` and `habit-add.colours`. |
| Auth | None. No sign-in, no cookies, no account screens. | `req~streakly.no-network~1`: never ask for an account or sign-in. |
| Integrations | None. No notification API is used, the service worker has no `push` handler, and no permission is ever requested. | `req~streakly.no-notifications~1`. |
| Look | The template's components and tokens, as DESIGN.md says. Light and dark come from the tokens and are set by `data-theme` on `<html>`. "System" follows `prefers-color-scheme`. Content sits in one centred column (max 640 px), long names wrap, and the week grid has a shrinking name column plus 7 equal day columns. | `req~streakly.theme~1` and `ac~streakly.layout.widths~1`: 8 habits with 40-character names fit at 375 and 1440 px in both themes. |
| Tests | Vitest covers `days.ts`, `streaks.ts` and `store.ts` (delete, delete-all, partial-failure abort, out-of-range refusal). It uses `fake-indexeddb` as the only dev dependency, because Node has no IndexedDB. Playwright covers every `e2e` item. It uses `page.clock` for midnight, `timezoneId` contexts for the time-zone change, `context.setOffline(true)` plus a request counter for `no-network`, and the test hook `window.__streakly` (built only when `NEXT_PUBLIC_TEST_HOOKS=1`) to seed data, hold loading, and make reads or writes fail. | Each item's `Needs:` asks for utest or e2e. States like "storage fails on write" and "hasn't finished" need a hook to reach. |
