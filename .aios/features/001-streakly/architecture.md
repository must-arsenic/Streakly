# Streakly: architecture

| Choice | Decision | Why |
|---|---|---|
| Parts | One part, `app`: an Expo 58 app (React Native 0.88, expo-router, TypeScript), built as is for the phone and exported to the web with `expo export --platform web`. On the web, `scripts/serve.mjs` serves it on port 3000 with cross-origin isolation, which SQLite's web build needs. The work falls into `src/app` (screens), `src/lib` (data, days, streaks, saving), `src/components` and `src/theme`. This is the Expo template, not `next-app`: the repo is built that way. | The spec makes Streakly "a real phone app" that "also runs in a browser up to 1440 px", and AXB AIOS decided the app kind is Expo, as the repo is built. |
| Pages | expo-router file routes, all drawn on the device; nothing is server-rendered. `src/app/_layout.tsx` is a Stack that opens the database before the first screen. `(tabs)/_layout.tsx` holds Today `/` (`index.tsx`), Week `/week` and Settings `/settings`, and redirects to the guide `/welcome` while `guideDone` is false. Add habit is `/habits/new` and Edit habit is `/habits/[id]`. `today.tsx` and `+not-found.tsx` redirect to `/`. Content sits in one centred column (`tokens.size.content`). | Screens guide, today, week, add-habit, edit-habit and theme; routes: "/today" and any unknown address go to Today; guide: the cards show "in place of Today, Week and Settings". |
| API | None: there's no server and no HTTP routes, and no `contract/openapi.yaml`. Screens call `src/lib/store.ts` directly: `loadList`, `loadHabit`, `loadSettings`, `addHabit`, `updateHabit`, `deleteHabit`, `toggleTick`, `setTick`, `saveTick`, `failedTick`, `reorder`, `setTheme`, `setGuideDone` and `deleteAll`. Each one throws on failure: a `RangeError` with the spec's text for a refusal, `TickNotSaved` (which carries the change) for a tick that didn't save. | Data and risk: "nothing is uploaded, nothing is shared and nothing updates live from elsewhere". |
| Data | SQLite on the device through `expo-sqlite` (`app.db`, `journal_mode=DELETE`, `synchronous=FULL`), opened in `src/lib/db.ts`. One queue serialises every query and every whole transaction. Tables are `habits(id, name, colour 0–7, position, created_on)`, `ticks(habit_id, date 'YYYY-MM-DD', PK(habit_id, date))` and `kv(key, value)`, which holds `theme`, `guideDone` and `failedTick`. They're made by the append-only `steps` in `db.ts` (`schema_version`). There are no uploads and no live events. | Data and risk lists exactly habits, ticks, the theme, the guide flag and at most one failed tick change, "on this phone only". |
| Auth | None. | "Nobody signs in". |
| Integrations | None. | The app is private and works offline; nothing is shared. |
| Look | Every style comes from `src/theme/tokens.ts`: light and dark palettes, plus 8 habit colours per scheme (Violet, Green, Amber, Red, Teal, Pink, Blue, Grey, in index order with Violet = 0). `use-palette.ts` resolves "system" against `useColorScheme`. `pnpm lint` (`scripts/tokens-only.mjs`) blocks raw values. On the web the `<html>` element gets `data-theme` and `color-scheme`. | theme: "System", "Light" and "Dark", applied at once; the glossary's 8 colours with Violet the default; light and dark themes. |
| Tests | Jest (`jest-expo`) runs `src/**/*.test.ts(x)` for the `utest` items (store, days, streaks), against a `node:sqlite` Db swapped in by `useDbForTests`. Playwright runs `e2e/` at 375×812 with touch for the `e2e` items, against the `dist-e2e` web export built with `EXPO_PUBLIC_AIOS_TEST_HOOKS=1`. The test hooks (`src/lib/test-hooks.ts`) are the `/__test/reset`, `/__test/seed?name=` and `/__test/force?route=&mode=empty\|slow\|error` routes; `faults.ts` makes writes or reads fail. JUnit output goes to `reports/`. | Each Done-when item's `Needs:`. The `save-error`, `list-states` and `edit-states` items need storage made to fail on demand. |
| Days | `src/lib/days.ts` keeps days as local `YYYY-MM-DD` strings. `canTick` checks a day against `lastSeven(today())` when the save runs. `use-today.ts` moves the date at local midnight, on returning to the foreground or tab focus, and on a 5 s poll. | tick-window, no-old-ticks, day-rollover (midnight within 10 s), and "Day boundaries follow the phone's local midnight". |
| Streaks | `src/lib/streaks.ts` works out `current` (ending today if today is ticked, otherwise yesterday) and `best` (the longest run) from the ticked dates on every render. They're never stored. | streaks: "worked out from the ticks each time and never stored". |
| Saving | Every change is one transaction over what it touches. `deleteHabit` and `deleteAll` remove ticks and habits together. `toggleTick` reads and writes in one transaction. `src/lib/use-save.ts` queues changes in order, so none is dropped, and shows "Couldn't save your change" with a "Try again" that reruns the same change. A failed tick goes into `kv.failedTick` as `{habitId, day, ticked}`; the retry runs `setTick` with that intended state and day, and a retry refused by the window clears it. | save-error, failed-tick-kept, no-lost-tick, no-partial-delete. |
| Reorder | `src/components/reorder-list.tsx` uses PanResponder with a 500 ms hold and an 8 px slop to pick a row up and drag it. The new order is saved with `reorder(ids)` into `position`, and the list changes only once the saved order comes back. Screen readers get "Move up" and "Move down" accessibility actions. A long press on the name doesn't open Edit. | reorder: the 500 ms long-press and drag, the screen-reader actions, and the long press that doesn't open Edit. |
